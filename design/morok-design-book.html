I

Concept

Morok is Russian for a glamour, an illusion: you see what is not there. An interface built on MOROK looks exactly like the layout in its HTML etalon, yet there is no browser in the app — only Rust, Core Text and Metal.

The kit grows out of a concrete pain: Quartz Commander, the Norton Commander clone and DOMOVOI each render through Metal on their own, and each writes text, layout and scrolling from scratch. MOROK does it once — and does it so that a screen drawn in /mneme:design with plain CSS and tokens carries over into the app almost mechanically.

The kit has no product "brand" of its own: an app's look is set by its tokens.css and its component CSS. This book shows the morok-base theme — a neutral "fog" and a single accent, the "will-o'-the-wisp". Apps start from it and depart from it by changing tokens.

MOROK

An illusion, not a browser

CSS is a description language, not a runtime. Styles compile at build time; a frame has no parser, no cascade and no DOM.

TISHINA

Zero when idle

No changes — no frame. The display link wakes on an event, an animation or a spring and goes back to sleep right after.

ISTOCHNIK

One source

Tokens live in a single tokens.css: the Chrome etalon renders from it and the Rust constants are generated from it. There is nowhere for them to drift apart.

II

Architecture

Two UI layers on top of a thin platform. Below — a retained element tree, a DOM analogue: stable IDs in an arena, styles, layout, accessibility, redraw of changed regions only. Above — declarative components on signals, as in SolidJS: a component function runs once, and a signal change updates exactly the nodes that depend on it.

Why Rust. Taffy (Block, Flexbox, Grid, calc()), AccessKit, objc2 and a stable language — versus months of hand-written Zig. The UI graph stays free of borrow-checker fights thanks to an arena and IDs.

VI

Styles: a CSS subset

A component's style is a real .css file. The build turns it into a static table: a class rule plus state overlays. A state change at runtime flips a flag; it does not recompute a cascade. Anything the subset does not support is a build error naming the file and line — never silently ignored.

/* components/button.css — what a MOROK component style looks like */
.button {
  display: inline-flex; align-items: center; gap: var(--space-2);
  height: 28px; padding: 0 var(--space-3);
  border-radius: var(--radius-sm);
  background: var(--color-surface); color: var(--color-text);
  box-shadow: var(--shadow-raised);

VII

Motion

Two sources of motion. Everything in etalons is CSS: transition and @keyframes with the same curves, carried over as is. Where macOS behaves physically — springs: scroll momentum, rubber banding at the edge, dragging. Motion holds the display link only while it runs.

motion-ease · 180
State changes, disclosure.
motion-ease-out · 280
Popovers and toasts appearing.
linear · 120
Progress and spinners only.

Spring: rubber banding at the edge

Drag the rectangle past the track and let go — this is how Scroll behaves at its edge: resistance grows with distance, and the return is a critically damped spring with no oscillation.

Respecting settings. With "Reduce motion" enabled in the system, transitions become instant, springs become short fades, and infinite animations stop.

VIII

Icons are SVG — the same files that sit in the etalon. The kit rasterizes them into an atlas for the required size and screen scale, so an icon in Chrome and in the app is one and the same. SF Symbols are not used: browsers do not know them, and the etalon would diverge from the app.

XI

Text input

Fields are plain text, single-line and multi-line. This is the most expensive part of the kit: caret, selection, IME through NSTextInputClient, system dictation, undo/redo, clipboard, wrapping and scrolling inside the field. Rich text and a code editor are not the kit's job.

XIII

Overlays and the AppKit boundary

Metal draws only inside its own window and cannot see the pixels of other windows. Hence the boundary: system parts stay native, and everything drawn in an etalon is drawn by MOROK — each overlay in its own borderless window so it can extend past the main window and the screen edge.

NATIVE · APPKIT

  • Menu bar — NSMenu, the same shortcuts
  • Window frame and traffic lights
  • Open / Save / Print — system panels
  • Blur behind the window — NSVisualEffectView under a transparent layer
  • ContextMenu — NSMenu by default

METAL · MOROK

  • Popover, Tooltip, Menu — borderless window, flips at the screen edge
  • Select, Combobox — a dropdown exactly as in the etalon
  • Toast — a stack in the window corner
  • Dialog / Sheet — inside the window, focus trap
  • ContextMenu — custom mode, when the etalon has its own menu
  • backdrop-filter — blur of what is inside the window

XV

Accessibility and keyboard

To the system a Metal view is a single picture. So every node with a role exposes an AccessKit node, and the tree is updated with deltas in the same frame as the pixels. VoiceOver and any tool that reads selected text through Accessibility see the app exactly as they see a native one.

XVII

Tokens

The canon is design/system/tokens.css. The HTML etalon renders from it, and the MOROK build generates Rust constants for the light and dark themes from it. The families color- space- radius- font- text- follow the /mneme:design format; shadow- and motion- are a kit extension that is yet to be legitimized.

/* design/system/tokens.css · light theme; dark — in @media (prefers-color-scheme: dark) with the same names */

Shadows belong only to what floats: menus, popovers, toasts, dialogs. Inside a window depth comes from lines and surface-sunken. Radii grow with surface scale.
